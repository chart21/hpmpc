# RESHARE_OPT_SIM=1: correct reshare-free MSB adders via mask baking

`RESHARE_OPT=1` replaces the first-level AND gates of the A2B MSB adders (RCA / PPA / PPA4) with
*reshared* gates: both input wires are re-shared with a correlated random multiplication
`(rt.a, rt.b = [a0 & a1])`, so the gate needs no per-gate `[lx·ly]` triple. The reshare of the
P1-owned wire (`s2 = -l2`, the bit-sliced conv/FC output mask) costs one preprocessing send per
reshared bit-slice: `delta = l ^ rt.a`.

`RESHARE_OPT_SIM=1` eliminates that send **correctly**: P1 *chooses* its conv/FC output mask so
that its A2B bit slices already equal its `rt.a` shares ("baking"), making `delta == 0` by
construction. P0 can then assume the delta without receiving it, and the skipped operations are
executed as real local gate ops with the exchanged value substituted by its guaranteed 0
(`reshare_b`: `m = 0, l = rt.a`; PPA4 input-wire `zero_add_local`: `m' = m, l' = assign`).

## How the bake works (protocols/beaver_triples.hpp)

The A2B transpose (`orthogonalize_boolean` / `real_ortho`) mirrors **both** indices:
value `j = e % BITLENGTH`, numeric bit `b` → slice `BITLENGTH-1-b`, lane-bit `BITLENGTH-1-j`
(slice 0 = MSB, slice 31 = LSB). `bake_reshare_mask(l, e)` therefore writes, for every reshared
slice `i` of the adder, bit `K-1-j` of `rt.a[base + g*R + t(i)]` into numeric bit `K-1-i` of `-l`,
where

* `g = e / BITLENGTH` is the value's A2B group (one adder per group),
* `base = curr_random_multiplication_index` at conv-mask time (nothing else consumes random
  multiplications between a layer's masking and its ReLU's adders),
* `e` includes `g_bake_batch_offset` (the conv layer runs one GEMM per batch element with
  layer-local indices, while the adders consume preprocessing batch-globally),
* `R = reshares_per_adder`, `t(i) = reshare_rt_offset(k, i)` mirror the generated circuits
  (RCA: only the LSB slice, `rt[0]`; PPA: slices 1..k-1 with `rt[i-1]`; PPA4-32:
  `{1,4,7,10,13,16,19,23,26,29,22} → rt[0..10]`, wire 22 last).

PPA4 additionally SIM-skips the input-wire `zero_add`s (3-tuple `.b`/`.c` fields at slices
`{2,5,8,...,30}`). This is exact only with **party-local** tuple fields (`.b` fully known to P0,
`.c` to P1, peer share 0), generated by `tuple3_gen(..., party_local_mode)` in nn/ConvTriple; P0
selects its A2B S1 masks as its `.b` fields (`g_a2b_s1_pending` peek), P1 bakes the `.c` fields
into the same conv mask.

A shared bias added after the GEMM shifts the output mask; the layer publishes the effective bias
mask shares (`g_bake_bias_l`) and the bake pre-compensates.

**P1-only rule:** every online bake must be gated to P1 (done inside `bake_reshare_mask`).
Baking P0's mask online desyncs P0's PRE-recorded masks from its live wires — its own
preprocessed corrections then corrupt the shares.

## Validation

The sensitive correctness check is `reshare_sim_check` in `reshare_b`: on P1 it counts, live,
whether the wire's `l` equals its `rt.a` share — the exact condition under which the SIM=1
execution is bit-identical to SIM=0. A summary (`RB-FINAL checks=... mismatch=...`) is printed at
exit. func53 additionally prints the counters for the Conv+ReLU test in isolation.

End-to-end tests alone are NOT sufficient: an RCA reshare error only perturbs the LSB carry
(sum shifts by ±2), which almost never flips the MSB — the original bake was completely
misaligned and still "passed".

### Residual mismatches (expected, harmless)

`RB-FINAL` reports a small non-zero mismatch count whenever a layer's output count is not a
multiple of BITLENGTH: the last A2B group is **padded**, and padding lanes belong to no value, so
nothing can bake them. The check compares whole `DATATYPE` words, so each padded group counts all
its adder's reshares as mismatched. LeNet (FC1: 1200 outputs = 37.5 groups, FC2: 840 = 26.25
groups → 2 padded groups) shows exactly `2 × R` residual mismatches: 2 (RCA), 62 (PPA), 22
(PPA4). Bit-sliced gates are lane-local and the substituted deltas keep both parties consistent,
so the resulting errors are confined to the unused padding lanes.

## Supported configurations (all validated with func53 + LeNet, CHEETAH_THREADS=4)

| Configuration                              | func53          | LeNet (10 imgs) |
|--------------------------------------------|-----------------|-----------------|
| plain, TRUNC_DELAYED=0, RCA/PPA/PPA4       | 8/8             | 100%            |
| plain, TRUNC_DELAYED=1, RCA/PPA/PPA4       | 6/8 (artifacts) | 100%            |
| MWK=1, TRUNC_DELAYED=0, RCA                | 8/8             | 100%            |
| MWK=1, TRUNC_DELAYED=0, PPA/PPA4           | unsupported (trunc image, see below) | — |
| MWK=1, TRUNC_DELAYED=1, RCA/PPA/PPA4       | 6/8 (artifacts) | 100%            |
| PUBLIC_WEIGHTS=1 (any trunc)               | falls back to SIM=0 (see below)      | 100% |

TRUNC_APPROACH > 0 is out of scope.

### MODELWEIGHTS_KNOWN_DURING_PREPROCESSING (MWK)

Under MWK, P1's output mask is tied to the triple share `r1` that it chooses freely and the triple
generation then forces onto its share (`l = TRUNC(-r1)`, SecureML). The bake is realized by constructing
`r1 = -((l_baked << FRACTIONAL) + low)` (`construct_mwk_r1_baked`; PRE and online use the same
chooser, so the PRNG draws match by construction). Since `TRUNC` is a logical shift, its image
zeroes the top FRACTIONAL mask bits — reshared slices at numeric bits ≥ K-FRACTIONAL **cannot**
be baked this way. RCA reshares only bit 0 and is exact; PPA/PPA4 reshare high bits and need
`TRUNC_DELAYED=1`, where the untruncated a_known variant applies (`l = -r1`, no constraint).
MWK conv and FC prescriptions are recorded in **separate** vectors (`g_mwk_p1_masks` /
`g_mwk_p1_fc_masks`): the triple generation processes all conv layers before all FC layers,
regardless of program order.

### PUBLIC_WEIGHTS=1

With public weights the conv/FC layers multiply locally — the output masks are *derived* from the
input masks (no fresh mask anywhere), so there is nothing to bake the reshare material into.
`config.h` therefore forces `RESHARE_OPT_SIM` back to 0 (real, communicating reshares) for
PUBLIC_WEIGHTS=1 builds. PW=1 + TRUNC_DELAYED=1 passes func53 (6/8, same artifacts as below) and
LeNet (100%).

## The two func53 failures under TRUNC_DELAYED=1 (test artifacts, not protocol bugs)

Under `TRUNC_DELAYED=1`, **every** build (including SIM=0 and non-MWK baselines) fails exactly two
func53 tests:

* **Convolution**: the test reveals the raw conv outputs. With delayed truncation the outputs
  still carry `2*FRACTIONAL` fractional bits (`got ≈ expected × 2^FRACTIONAL`) — the truncation
  only happens at the *next* ReLU, which this test does not run.
* **BatchNorm**: same reveal-before-truncation effect on the BN output scaling.

These do **not** occur in LeNet (or any real network): intermediate outputs are never revealed —
every conv/FC output passes through the following ReLU (which performs the delayed truncation)
before anything is opened, and the framework truncates the final layer before argmax. All LeNet
TRUNC_DELAYED=1 configurations above reach 100%.

## Known limitations

* Wires whose masks are not produced by a baked conv/FC/remask path (e.g. inputs shared directly
  in unit tests) cannot skip their reshares; a real implementation would keep the reshare send for
  them. The func53 tests bake their ReLU inputs via `remask(dst, n, /*bake=*/true)`.
* MWK + TRUNC_DELAYED on the non-tiled conv paths (INTERLEAVE_COMM=0, CUDA GEMM) keeps the
  SecureML truncation (combination unsupported there).
* DATTYPE must equal BITLENGTH (no SIMD lane packing across values).
